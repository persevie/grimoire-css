# v1.9.0

Grimoire CSS adds an MCP server for AI-assisted project work and brings the
canonical CSS-to-Scroll Transmutator into the main Rust crate and CLI.

### Added

- Optional stdio MCP server (`grimoire_css_mcp`, feature `mcp`) with 19 tools and
  four resources: the agent primer, component catalog, config schema and documentation.
- Project-root configuration at launch, structured Analyzer results, spell/config
  validation and a project check that runs lint and the real filesystem build.
- MCP access to existing init, build, shorten, references, statistics and DRY operations.
- Typed `transmute_css` / `transmute_paths` APIs and the `transmute` CLI command.
- MCP CSS preview and import with conflict checks, explicit replacement, atomic
  file installation and rollback when project verification fails.
- MCP release binaries for Linux x64, macOS x64/arm64 and Windows x64.

### Fixed

- Spell explanations compile the exact parsed token, preserving quoted values;
  unterminated quoted values are rejected. Prefix delimiters inside strings or
  selector suffixes are no longer interpreted as spell syntax.
- CSS migration retains compound and descendant selectors, class selectors after
  child combinators, and media conditions across selector lists and nested queries.
- Comments retain CSS token boundaries without introducing descendant combinators.
- Literal underscores survive migration in selector suffixes, strings, URLs and
  custom-property references. Duplicate declarations retain their last cascade position.
- Unicode whitespace and escaped tabs/spaces survive migration inside CSS
  identifiers, including trailing escaped spaces. File imports reject URLs whose
  source base cannot be preserved and identify the originating CSS file.
- CSS strings and selector attribute values retain literal whitespace and correctly
  consume escaped line continuations during migration.
- CSS dollar literals are protected from Grimoire substitution, and empty custom
  properties are accepted. Component/Scroll collisions are rejected before import;
  replacements are validated against the definitions that remain.
- Migration rejects class names the engine cannot invoke as Scrolls before writing
  an import, instead of reporting success with missing styles.
- Migration rejects potential cascade conflicts between different Scrolls before
  writing, with selector/declaration diagnostics and the existing `shared.styles`
  fallback. Ordinary Scroll ordering is unchanged; ambiguous cases are rejected
  conservatively instead of reporting a conversion with changed cascade behavior.
- Unsupported CSS at-rules and selectors fail explicitly instead of silently
  disappearing from a successful conversion.
- Cyclic Scroll inheritance returns a configuration error instead of overflowing
  the process stack.
- Browserslist I/O failures return build errors, allowing failed imports to roll
  back their files instead of terminating the MCP server.
- External configuration discovery treats glob characters in the project root literally.
- Read-only Analyzer operations avoid creating or pruning project directories;
  MCP calls discard buffered CLI messages.

### Release checks

- CI checks default, minimal, MCP and combined feature configurations, with native
  macOS and Windows checks in addition to Linux.
- Publication depends on quality and coverage checks. Release notes are checked
  before publication; release builds and publishing use the lockfile.
- All-feature Clippy checks include the LSP test module.

### Usage and limits

Build with `cargo build --release --features mcp --bin grimoire_css_mcp` and launch
with `--root /absolute/path/to/project`. The server uses MCP revision 2025-11-25.
See [MCP in the README](https://github.com/persevie/grimoire-css/blob/v1.9.0/README.md#mcp-server) for installation, client configuration and the tool reference.

Migration supports selectors beginning with a class and media queries. Rules such
as `@layer`, `@supports`, `@keyframes` and `@import`, and selectors without a leading
class, must be handled separately; they cause an explicit conversion error.

Project checks and imports can write build outputs. The imported Scroll file is
rolled back on failed verification; ordinary build outputs are not transactional.
Validation proves engine acceptance and build success, not visual equivalence to
a design. The minimum supported Rust version remains 1.93.0.
